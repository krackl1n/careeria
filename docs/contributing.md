# Как писать документацию

Страницы — обычные Markdown-файлы в `docs/`. Сайт, поиск, меню и обновление при редактировании предоставляет MkDocs с темой Material.

## Новая страница

Создайте `.md` с заголовком H1. Навигация строится автоматически из существующих страниц в `docs/`, поэтому удалённый файл не блокирует сайт. Пишите обычные относительные ссылки на Markdown-страницы, например `[Контекст](architecture/c4-plant-uml/plantuml/context/system-context.md)`.

MkDocs преобразует их в адреса HTML-страниц. Ссылка на `.puml` открывает исходник; для перехода к странице диаграммы используйте `.md`.

## Диаграммы

C4-схемы и описания находятся в `architecture/c4-plant-uml/plantuml/`. Сохранены папки уровней C4, тематических проекций и областей команды.

В Markdown используется блок с языком `plantuml`, внутри которого находятся `@startuml`, `!include <путь к .puml>` и `@enduml`. Готовый пример — [системный контекст](architecture/c4-plant-uml/plantuml/context/system-context.md).

Пути в `!include` считаются от каталога `docs/`: `architecture/c4-plant-uml/plantuml/context/system-context.puml`. Внутренние include самой схемы остаются относительными к её `.puml`.

Текст до и после блока отображается до и после диаграммы. Плагин `plantuml-markdown` создаёт встроенный SVG: ссылки на элементах работают, а CSS сохраняет пропорции. Для других UML-диаграмм применяется тот же блок.

## Несколько диаграмм в одном файле

В интеграционных `.puml` каждый блок имеет нативную PlantUML-секцию `!startsub <ID>` / `!endsub`. Отдельная Markdown-страница подключает её через `!includesub <путь к файлу>!<ID>`. Это позволяет показывать L1 и L2 по отдельности и сохранять исходный файл с обеими диаграммами.

## Переходы внутри C4

Укажите у элемента `$link` с адресом страницы сайта. Например, адрес контейнерного представления: `/architecture/c4-plant-uml/plantuml/container/full-system/`. Такой переход уже добавлен на элемент Careeria в системном контексте. При размещении сайта в подкаталоге адреса абсолютных ссылок потребуется адаптировать.

## Вложения и проверка

Фотографии и файлы храните рядом со страницей или в `assets/` и подключайте обычными Markdown-ссылками. MkDocs копирует их в статический сайт.

```sh
make docs-test
make architecture-validate
```

`make docs` запускает MkDocs в Docker и автоматически обновляет открытый сайт при изменениях, включая изменения общих `.puml`-фрагментов. Кеш рендера расширения отключён, чтобы include-файлы не оставляли устаревшие схемы.

Сгенерированные страницы в `.site-docs/` не редактируются и не добавляются в Git. MkDocs требует, чтобы этот каталог находился вне `docs/`.
