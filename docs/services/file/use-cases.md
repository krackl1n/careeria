# File Service: функции и юзкейсы

Проектный каталог по [контейнеру L2](../../architecture/c4/plantuml/model/infrastructure-elements.puml), потребностям доменных сервисов и [проекту File Service](index.md). Отдельной L3 File Service пока нет; названия компонентов и операций — предложения, не реализованные RPC.

Доменный сервис управляет файлом в рамках разрешённого ресурса и purpose. Пользователь взаимодействует через этот сервис; байты отправляются непосредственно в Object Storage по ограниченному праву. Планировщик, Object Storage и сканер — технические участники. Диаграмма группирует цели, не задаёт права или сетевой маршрут.

| ID / сценарий | Предлагаемый компонент | Инициатор и результат | Проверки и открытые вопросы |
|---|---|---|---|
| F01 BeginUpload | File Upload Service | Доменный сервис начинает загрузку и получает устойчивые file/session/operation ID. | Владелец, purpose и target проверяются; повтор того же operation ID с тем же запросом возвращает исходный результат. Создание multipart в S3 требует восстановления после потери ответа. |
| F02 GetUpload / RenewUploadURL | File Upload Service | Доменный сервис получает состояние или новое краткоживущее право загрузки. | Проверяются вызывающий сервис, срок и состояние; временные URL не сохраняются как идемпотентный ответ. |
| F03 CompleteUpload | File Upload Service | Подтверждает загрузку и инициирует проверку конкретной версии объекта. | Завершение не означает READY; повтор и ответ после отмены должны быть безопасны. |
| F04 CancelUpload | File Upload Service | Отменяет незавершённую сессию и планирует очистку. | Не обещает мгновенного удаления S3; ранее выданные права и возможные поздние записи учитываются. |
| F05 CheckFile | File Validation Service | Проверяет содержимое, MIME, размер, checksum и безопасность точной версии; фиксирует результат. | Только полный успешный набор проверок даёт READY. Недоступность сканера — техническая ошибка, не успешная проверка. |
| F06 GetFileStatus / GetOperation | File Upload / Binding Service | Уполномоченный сервис получает безопасное состояние файла или результат устойчивой операции. | File ID или operation ID без авторизации не дают доступ к метаданным другого пользователя. |
| F07 BindFile | File Binding Service | Привязывает READY-файл к разрешённому ресурсу, включая независимую привязку для отклика. | Проверяется вызывающий сервис, цель и делегирование; файл в DELETING/DELETED не привязывается. |
| F08 ReleaseBinding | File Binding Service | Освобождает только принадлежащую сервису привязку. | Повтор по operation ID идемпотентен; другие привязки сохраняются. |
| F09 GetDownloadURL | File Binding Service | Возвращает ограниченную ссылку на конкретную проверенную версию после авторизации. | Нужен ACTIVE binding и право на ресурс; старый URL может работать до истечения после отзыва. |
| F10 ReconcileAndCleanup | File Cleanup Worker | Восстанавливает незавершённые операции, освобождает multipart и неиспользуемый объект. | Нет ACTIVE/PENDING binding; учтены выданные права записи, storage versions, повторы и поздние результаты. |

Неверный формат, запрет доступа, конфликт operation ID, неизвестный ресурс, неподходящее состояние, незавершённая/отклонённая проверка и недоступность хранилища или сканера различаются в контракте. Их точные HTTP/gRPC коды и политика сокрытия существования файла ещё не определены. Сообщение о READY, если будет событием, требует отдельного соглашения о доставке и повторной проверке состояния.
