# Notification Service: функции и юзкейсы

Проектный каталог по [C4 L3](../../architecture/c4/plantuml/system-context%28L1%29/full-system%28L2%29/notification-service%28L3%29/index.md) и [проекту сервиса](index.md), не список реализованных RPC. Единственный показанный application service — Notification Service; остальные блоки выполняют роли входных и выходных адаптеров, хранения и workers.

Сервис-инициатор имеет доверенную identity и право отправки; пользователь получает доступ к собственному inbox и stream. Events Consumer и Worker Pool — технические инициаторы. Провайдер принимает внешний запрос, но его ответ не доказывает прочтение пользователем.

| ID / сценарий | Точка входа | Результат | Правила и неопределённости |
|---|---|---|---|
| N01 Schedule | gRPC Server → Notification Service | Создаётся задача для получателя, канала и редакции шаблона на заданное время. | Инициатор и получатель проверяются; в рамках срока идемпотентности одинаковый ключ и запрос возвращают тот же результат. Источник адреса и правила локали не определены. |
| N02 Cancel | gRPC Server → Notification Service | PENDING/RETRY-задача отменяется. | При PROCESSING — конфликт: внешний вызов мог начаться. Отмена не отзывает уже принятое провайдером сообщение и другие каналы. |
| N03 ProcessEvent | Events Consumer → Notification Service | Из бизнес-события создаётся полный набор задач, событие отмечается обработанным до commit offset. | Дедупликация и набор jobs в одной транзакции; политика ошибочных событий и крупного fan-out требует решения. |
| N04 FetchPending | Worker Pool → Notification Service | Ограниченная порция готовых задач закрепляется lease. | `SKIP LOCKED` в короткой транзакции; срок и token сохраняются до выполнения. |
| N05 Execute | Worker Pool → Notification Service | Шаблон рендерится, попытка фиксируется и сообщение направляется провайдеру либо сохраняется в inbox. | Внешняя сеть вне транзакции; устаревший lease не может записать результат. Внешние дубли после неопределённого ответа возможны. |
| N06 Retry / RecoverLease | Worker Pool → Notification Service | Временная ошибка или истёкший lease приводят к повтору по политике. | Retry limit, backoff и неопределённый результат провайдера требуют согласования; повтор не обещает exactly-once. |
| N07 GetInbox | gRPC Server → Notification Service | Пользователь получает ограниченную страницу своего inbox. | Получатель берётся из доверенного контекста; курсор и лимиты требуют контракта. История попыток доставки — другое представление. |
| N08 ConnectStream | Stream Server | Пользователь получает события собственного inbox в подключённом потоке. | Stream не заменяет постоянное хранение; полное восстановление после разрыва и доставка между репликами пока не определены. |

Отметка прочтения, пользовательское удаление, настройки каналов, управление шаблонами и provider callbacks пока не входят в утверждённые RPC L3. Редакции шаблонов предложены моделью, но способ их создания и публикации требует отдельного сценария. Ошибки формы, прав, конфликта идемпотентности и состояния, ошибки шаблона и недоступности зависимости должны различаться.
