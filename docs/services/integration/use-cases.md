# Integration Service: функции и юзкейсы

Проектный каталог по [C4 L3](../../architecture/c4/plantuml/system-context%28L1%29/full-system%28L2%29/integration-service%28L3%29/index.md) и [проекту сервиса](index.md), не перечень реализованных RPC. Сохранены три application service: Management, Inbound и Outbound.

Администратор управляет только разрешёнными интеграциями компании; внешняя HR-система аутентифицируется подписью, а не пользовательской сессией. Kafka и Delivery Worker — технические инициаторы. Овалы группируют цели и не задают права.

| ID / сценарий | Компонент | Результат | Условия и открытые вопросы |
|---|---|---|---|
| M01 Create / UpdateConnection | Management | Создано или изменено подключение компании, mapping и разрешённые события. | Право проверяется по компании; tenant и уникальность подключения требуют контракта. |
| M02 Pause / Resume / RevokeConnection | Management | Изменён жизненный цикл подключения. | REVOKED терминален; гонки с приёмом и уже начатой отправкой требуют протокола. |
| M03 RotateSigningKey | Management | Добавлен новый ключ и выполнен контролируемый переход версий. | Входные и выходные ключи разделены; безопасная выдача и экстренный отзыв должны быть согласованы. |
| M04 Create / UpdateSubscription | Management | Создана подписка или новая редакция назначения/контракта. | Endpoint не активируется без проверки; смена URL не переписывает старые deliveries. |
| M05 VerifyWebhookEndpoint | Management | Проверяется владение endpoint и разрешается его активация. | Точный handshake, доказательство и срок действия ещё не спроектированы; текущая БД не гарантирует проверку. |
| M06 Pause / Resume / DeleteSubscription | Management | Управление подпиской без удаления истории. | Влияние на ожидающие и уже начатые доставки требует решения. |
| M07 List / GetConnections, Receipts, Deliveries, Attempts | Management | Уполномоченный пользователь читает ограниченные журналы своей компании. | Секреты, подписи, полные внешние ответы и чужие tenant-данные скрываются. |
| M08 Redrive / CancelDelivery | Management | Ручной повтор FAILED или отмена будущих попыток. | Cancel не отзывает начатый HTTP; redrive, дедлайн и аудит требуют контракта. |
| I01 ReceiveInboundWebhook | Inbound | Подлинный запрос принят, зафиксированы receipt и при необходимости нормализованное событие. | Raw body, подпись, свежесть, тип и tenant проверяются до commit; успех — приём, не доменное применение. |
| I02 HandleDuplicate / IgnoreUnsupported | Inbound | Повтор возвращает прежний receipt; разрешённый известный тип может быть устойчиво IGNORED. | Совпадающий ID с другим digest — конфликт; просроченная подпись не обходится дедупликацией. |
| O01 PlanOutboundDeliveries | Outbound + Events Consumer | На внутреннее событие созданы все разрешённые доставки. | Tenant определяется доверенным событием и подключением; дедупликация и jobs фиксируются до commit offset. |
| O02 Execute / RetryDelivery | Outbound + Worker | Захвачена доставка и выполнена подписанная HTTP-попытка. | Устойчивый ID и байты, lease/fencing, защита destination; дубли у получателя возможны. |
| O03 RecoverExpiredLease | Outbound + Worker | Истёкшая попытка зафиксирована как UNKNOWN, доставка может быть повторена. | UNKNOWN не доказывает отсутствие обработки получателем; дедупликация на его стороне обязательна для повторов. |

Ошибки неверной формы, подписи, устаревшего времени, прав, недопустимого состояния, конфликта digest, недоступности зависимостей и временной ошибки доставки должны различаться в протоколах. Точные коды, лимиты, retry policy и правила пользовательского доступа требуют утверждения. Подробности транзакций и SSRF-проверок — в [проекте сервиса](index.md#delivery).
