# Assessment Service: функции и юзкейсы

Каталог — проект, не список реализованных RPC. Сценарии основаны на [C4 L3](../../architecture/c4/plantuml/system-context%28L1%29/full-system%28L2%29/assessment-service%28L3%29/index.md) и [проекте сервиса](index.md). Сохранены два прикладных компонента: Assessment Template Service и Session Execution Service.

Рекрутер управляет шаблонами и назначениями при наличии прав; кандидат выполняет только свои испытания; интервьюер проверяет назначенную ему сессию. Hiring может инициировать назначение по будущему межсервисному контракту. Планировщик — технический инициатор. На диаграмме сгруппированы цели, а не разрешения.

| ID / операция | Компонент | Инициатор и результат | Проверки и ограничения |
|---|---|---|---|
| T01 CreateTemplate | Assessment Template Service | Представитель создаёт шаблон и черновую редакцию. | Company ID и право управления проверяются; черновик может быть неполным. |
| T02 UpdateTemplate | Assessment Template Service | Представитель меняет черновую редакцию, задачи и настройки. | Активные сессии сохраняют исходную редакцию; опубликованная редакция не перезаписывается. |
| T03 PublishRevision | Assessment Template Service | Представитель публикует готовую редакцию. | Как минимум одна задача, допустимый лимит и порог; публикация и редакции — уточнение L3. |
| S01 AssignAssessment | Session Execution Service | Рекрутер или Hiring назначает опубликованную редакцию кандидату на отклик, получает SCHEDULED-сессию. | Права, соответствие candidate/application и дедлайн необходимо проверить по согласованному контракту; повтор не создаёт дубль. |
| S02 GetMyAssignedAssessments | Session Execution Service | Кандидат получает страницу своих назначений. | Связь Candidate ID с identity должна быть доверенно определена; чужие сессии недоступны. |
| S03 StartSession | Session Execution Service | Кандидат начинает SCHEDULED-сессию, получает сроки и разрешённые задания. | До valid_until; через CAS версии фиксируются started_at и expires_at. Скрытые тесты не выдаются. |
| S04 GetSessionDetails | Session Execution Service | Авторизованный участник получает разрешённые сведения. | Доступ к заданиям, закрытым тестам, ответам и отзывам разделён. |
| S05 SubmitTaskSolution | Session Execution Service | Кандидат отправляет решение; создаются попытка и устойчивая задача проверки. | Сессия IN_PROGRESS и не истекла, задача из её редакции, язык допустим. Runner вызывается вне транзакции. |
| S06 PollSubmissionResult | Session Execution Service | Авторизованный участник узнаёт статус и разрешённые метрики попытки. | Скрытые тест-кейсы, секреты и чужие решения не раскрываются; детализация требует политики. |
| S07 InitializeLiveCoding | Session Execution Service | Разрешённый кандидат или интервьюер получает ограниченный доступ к комнате. | Только подходящий тип испытания; идемпотентность комнаты, время жизни токена и cleanup нужно определить. |
| S08 FinalizeSession | Session Execution Service | Кандидат завершает IN_PROGRESS-сессию и переводит её в SUBMITTED. | Дедлайн проверяется в транзакции; незавершённые проверки не считаются результатом. |
| S09 SubmitManualReview | Session Execution Service | Назначенный интервьюер оставляет оценку и отзыв. | Диапазон баллов 0–100, права и рубрика проверяются; изменение и поздняя подача требуют решения. |
| S10 CalculateSessionScore | Session Execution Service | После готовности входных данных стратегия фиксирует EVALUATED и событие. | Правила выбора попыток, веса, версия алгоритма и конкуренция ещё не определены. |
| S11 GetAssessmentReport | Session Execution Service | Уполномоченный представитель получает разрешённый отчёт. | Отдельная политика доступа к исходному коду, ответам, отзывам и результату. |
| S12 ReconcileExpiredSessions | Session Expiry Worker | Планировщик обрабатывает просроченные сессии. | Задержка worker не продлевает срок; worker есть в тексте, но не показан на диаграмме L3. |
| S13 Dispatch / ReconcileRunner | Предлагаемый dispatcher + Sandbox Client | Устойчиво передаёт попытку в Runner и согласует результат. | Требует дополнения C4, дедупликации operation ID, повторов, lease и политики поздних результатов. |

Операции изменения проверяют версию и выполняют запись состояния и события атомарно. Идемпотентные повторы и ответы после дедлайна должны обрабатываться по контракту. Ошибки доступа, неверного состояния, истечения, конфликта версии и недоступности зависимости различаются. Участие в оценке не даёт автоматического доступа к остальным данным кандидата.
