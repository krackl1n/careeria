# Примеры IDEF0 с русскими названиями

Все примеры ниже можно вставить в любую `.md`-страницу внутри `docs/`. Ключевые слова и команды пишутся по-английски, русские имена функций и стрелок заключаются в бэктики. Внешняя рамка с пометкой `markdown` показывает исходный код, а следующая за ней схема построена из такого же блока `idef0`. При сохранении страницы `make docs` перерисует результат. [Справочник команд](01-commands.md) объясняет синтаксис каждой строки.

## 1. Один блок: контекст функции

Начните с функции «Согласовать вакансию». Четыре строки описывают её интерфейс: вход слева, правило сверху, исполнителя снизу и результат справа. `@view focus` явно просит показать один блок.

````markdown
```idef0
@view focus `Согласовать вакансию`
`Согласовать вакансию` receives `Черновик вакансии`
`Согласовать вакансию` respects `Правила публикации`
`Согласовать вакансию` requires `Рекрутер`
`Согласовать вакансию` produces `Согласованная вакансия`
```
````

Так он выглядит на странице:

```idef0
@view focus `Согласовать вакансию`
`Согласовать вакансию` receives `Черновик вакансии`
`Согласовать вакансию` respects `Правила публикации`
`Согласовать вакансию` requires `Рекрутер`
`Согласовать вакансию` produces `Согласованная вакансия`
```

| Строка | Что видно на схеме |
| --- | --- |
| `` receives `Черновик вакансии` `` | Входящая стрелка слева. |
| `` respects `Правила публикации` `` | Управляющая стрелка сверху. |
| `` requires `Рекрутер` `` | Механизм снизу. |
| `` produces `Согласованная вакансия` `` | Выходящая стрелка справа. |

Здесь нет дочерних функций. Поэтому `` @view auto `Согласовать вакансию` `` дал бы тот же вид `focus`. Если удалить `@view` совсем, корень без дочерних функций также будет показан как один блок.

## 2. Три уровня, цвета и SVG для другой страницы

Теперь опишем обработку отклика. В одном блоке находится **вся модель**: корневая функция, два дочерних блока и ещё два блока внутри проверки. Три `@view` показывают её последовательно как контекст A-0, декомпозицию A0 и декомпозицию проверки A1.

```text
Обработать отклик кандидата
├── Проверить отклик кандидата по требованиям вакансии
│   ├── Проверить опыт
│   └── Сопоставить с требованиями
└── Принять решение по отклику
```

Вставьте весь блок целиком. Названия функций и стрелок в строках `@view`, `@block` и `@arrow` должны точно совпадать с названиями в модели.

````markdown
```idef0
@export obrabotka-otklika.svg
@view focus `Обработать отклик кандидата`
@view decompose `Обработать отклик кандидата`
@view decompose `Проверить отклик кандидата по требованиям вакансии`

@defaults arrow=#43566D arrow_text=#26384B block_fill=#F3F7FB block_stroke=#27466A block_text=#172B41
@block `Принять решение по отклику` | fill=#EAF6EE stroke=#15803D text=#14532D
@arrow `Решение по отклику` | stroke=#15803D text=#14532D

# A-0: интерфейс всей функции
`Обработать отклик кандидата` receives `Отклик кандидата`
`Обработать отклик кандидата` respects `Правила отбора`
`Обработать отклик кандидата` requires `Команда подбора`
`Обработать отклик кандидата` produces `Решение по отклику`

# A0: две дочерние функции
`Обработать отклик кандидата` is composed of `Проверить отклик кандидата по требованиям вакансии`
`Обработать отклик кандидата` is composed of `Принять решение по отклику`
`Проверить отклик кандидата по требованиям вакансии` receives `Отклик кандидата`
`Проверить отклик кандидата по требованиям вакансии` respects `Правила отбора`
`Проверить отклик кандидата по требованиям вакансии` requires `Команда подбора`
`Проверить отклик кандидата по требованиям вакансии` produces `Результат проверки`
`Принять решение по отклику` receives `Результат проверки`
`Принять решение по отклику` produces `Решение по отклику`

# A1: раскрываем первый блок A0
`Проверить отклик кандидата по требованиям вакансии` is composed of `Проверить опыт`
`Проверить отклик кандидата по требованиям вакансии` is composed of `Сопоставить с требованиями`
`Проверить опыт` receives `Отклик кандидата`
`Проверить опыт` respects `Правила отбора`
`Проверить опыт` produces `Оценка опыта`
`Сопоставить с требованиями` receives `Оценка опыта`
`Сопоставить с требованиями` requires `Команда подбора`
`Сопоставить с требованиями` produces `Результат проверки`
```
````

Этот же блок отрисован здесь:

### Почему границы совпадают

| Уровень | Стрелки раскрываемого блока | Внешние стрелки его дочерней схемы |
| --- | --- | --- |
| A-0 → A0 | `Отклик кандидата` (Input), `Правила отбора` (Control), `Команда подбора` (Mechanism), `Решение по отклику` (Output). | Те же четыре пары роли и имени: вход и правило у проверки, механизм у проверки, выход у решения. |
| A0 → A1 | `Отклик кандидата` (Input), `Правила отбора` (Control), `Команда подбора` (Mechanism), `Результат проверки` (Output). | Те же пары: вход и правило у «Проверить опыт», механизм и выход у «Сопоставить с требованиями». |

`Оценка опыта` и `Результат проверки` связывают соседние блоки **внутри** своих уровней. Для внутренних стрелок `@tunnel` не нужен. Длинное имя блока «Проверить отклик кандидата по требованиям вакансии» переносится внутри прямоугольника. `@defaults` задаёт палитру всей модели, `@block` выделяет только решение, а `@arrow` окрашивает итоговый результат.

`@export` создаёт рядом с этой страницей [контекст](obrabotka-otklika.svg), [A0](obrabotka-otklika-2.svg) и [A1](obrabotka-otklika-3.svg). Число в имени соответствует порядку строк `@view`. Например, на странице `docs/project/otkliki.md` можно показать A0 так:

```markdown
![Обработка отклика: уровень A0](../contributing/idef0/obrabotka-otklika-2.svg)
```

После изменения исходного блока SVG пересоздаются при `make docs` или `make idef0-render`. Для повторного использования модели с независимым выбором видов на разных страницах вынесите те же строки без `@`-команд в `.idef0`, а виды и цвета — в соседний `.idef0.json`, как описано в [основном руководстве](index.md#idef0-file).

## 3. Два вида туннелей на дочерней схеме

Схема «Сформировать короткий список» состоит из отбора откликов и подготовки списка. На A0 блок «Отобрать подходящие отклики» получает `Политика найма` сверху. При его раскрытии политика опущена, зато появляется `Сервис проверки`, которого нет на родительском блоке. Оба отличия нужно явно пометить.

````markdown
```idef0
@view decompose `Сформировать короткий список`
@view decompose `Отобрать подходящие отклики`
@tunnel parent | `Отобрать подходящие отклики` | control | `Политика найма`
@tunnel child | `Отобрать подходящие отклики` | mechanism | `Сервис проверки`

`Сформировать короткий список` receives `Отклики кандидатов`
`Сформировать короткий список` respects `Политика найма`
`Сформировать короткий список` requires `Рекрутер`
`Сформировать короткий список` produces `Короткий список`
`Сформировать короткий список` is composed of `Отобрать подходящие отклики`
`Сформировать короткий список` is composed of `Подготовить короткий список`

`Отобрать подходящие отклики` receives `Отклики кандидатов`
`Отобрать подходящие отклики` respects `Политика найма`
`Отобрать подходящие отклики` requires `Рекрутер`
`Отобрать подходящие отклики` produces `Отобранные отклики`
`Подготовить короткий список` receives `Отобранные отклики`
`Подготовить короткий список` produces `Короткий список`

`Отобрать подходящие отклики` is composed of `Проверить профиль`
`Отобрать подходящие отклики` is composed of `Оценить соответствие`
`Проверить профиль` receives `Отклики кандидатов`
`Проверить профиль` requires `Сервис проверки`
`Проверить профиль` produces `Данные профиля`
`Оценить соответствие` receives `Данные профиля`
`Оценить соответствие` requires `Рекрутер`
`Оценить соответствие` produces `Отобранные отклики`
```
````

Результат:

```idef0
@view decompose `Сформировать короткий список`
@view decompose `Отобрать подходящие отклики`
@tunnel parent | `Отобрать подходящие отклики` | control | `Политика найма`
@tunnel child | `Отобрать подходящие отклики` | mechanism | `Сервис проверки`

`Сформировать короткий список` receives `Отклики кандидатов`
`Сформировать короткий список` respects `Политика найма`
`Сформировать короткий список` requires `Рекрутер`
`Сформировать короткий список` produces `Короткий список`
`Сформировать короткий список` is composed of `Отобрать подходящие отклики`
`Сформировать короткий список` is composed of `Подготовить короткий список`

`Отобрать подходящие отклики` receives `Отклики кандидатов`
`Отобрать подходящие отклики` respects `Политика найма`
`Отобрать подходящие отклики` requires `Рекрутер`
`Отобрать подходящие отклики` produces `Отобранные отклики`
`Подготовить короткий список` receives `Отобранные отклики`
`Подготовить короткий список` produces `Короткий список`

`Отобрать подходящие отклики` is composed of `Проверить профиль`
`Отобрать подходящие отклики` is composed of `Оценить соответствие`
`Проверить профиль` receives `Отклики кандидатов`
`Проверить профиль` requires `Сервис проверки`
`Проверить профиль` produces `Данные профиля`
`Оценить соответствие` receives `Данные профиля`
`Оценить соответствие` requires `Рекрутер`
`Оценить соответствие` produces `Отобранные отклики`
```

| Пара «роль + имя» | На блоке A0 | На границе A1 | Команда |
| --- | --- | --- | --- |
| Input `Отклики кандидатов` | Есть. | Есть, код `I1`. | Не нужна. |
| Mechanism `Рекрутер` | Есть. | Есть, код `M1`. | Не нужна. |
| Output `Отобранные отклики` | Есть. | Есть, код `O1`. | Не нужна. |
| Control `Политика найма` | Есть, показаны скобки у блока. | Отсутствует. | `@tunnel parent`. |
| Mechanism `Сервис проверки` | Отсутствует. | Есть со скобками у границы, без ICOM-кода. | `@tunnel child`. |

Если убрать одну из строк `@tunnel`, вместо схемы появится `boundary mismatch`, который перечислит несовпадающие пары. Имя и роль в команде должны соответствовать именно этому различию. На корневом уровне «Сформировать короткий список» все четыре граничные стрелки совпадают с интерфейсом A0, поэтому для него туннели не объявляются.

## Как продолжить со своей моделью

1. Скопируйте ближайший по смыслу пример в новую Markdown-страницу и переименуйте функции и стрелки.
2. Добавляйте дочерние функции строками `is composed of`. Для каждого нового уровня добавьте `` @view decompose `Имя функции` ``.
3. Сверьте пары «роль + имя» между раскрываемым блоком и внешней границей дочерней схемы. Отличия либо исправьте, либо точно отметьте `@tunnel`.
4. Добавьте цвета, если они помогают читать схему. Для отдельного SVG добавьте `@export` и проверьте созданные файлы рядом со страницей.
5. Запустите `make docs`, откройте все виды, затем проверьте `make idef0-render` и сборку документации.

Другие готовые модели с отдельными `.idef0` и JSON находятся в [примерах уровней и границ](02-examples.md).
