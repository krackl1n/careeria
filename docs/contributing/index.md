# Как писать документацию

Документация Careeria — исходные Markdown-страницы, текстовые модели и схемы, из которых MkDocs собирает сайт. Пишите объяснение рядом с моделью: читатель должен понять назначение страницы, границы описываемой части системы и смысл диаграммы без изучения исходного кода.

## Разделы этого руководства

| Раздел | Что в нём описано |
| --- | --- |
| [Структура и страницы](01-structure.md) | Где хранить страницы и вложения, как устроены меню, заголовки, ссылки и шаблон новой страницы. |
| [IDEF0](02-idef0.md) | Функциональная модель, ICOM-стрелки, вложенность, цвета, синхронизация SVG и подключение на страницу. |
| [PlantUML и C4](03-plantuml.md) | Исходники `.puml`, встроенный рендер, `!include`, несколько видов из одного файла и переходы между схемами. |

## Что за что отвечает

| Часть | Назначение | Что редактировать |
| --- | --- | --- |
| `docs/**/*.md` | Текст и страницы сайта. Заголовки H1 образуют названия страниц. | Markdown-страницы. |
| `docs/idef0-svg/models/*.idef0` | Функции, ICOM-связи и вложенность IDEF0. | Исходную модель. |
| `docs/idef0-svg/models/*.idef0.json` | Выбранные виды модели и цвета элементов. | JSON рядом с моделью. |
| `docs/idef0-svg/models/*.svg` | Готовые IDEF0-изображения для Markdown. | Перегенерировать из модели; не править вручную. |
| `docs/architecture/c4-plant-uml/plantuml/**/*.puml` | Исходники архитектурных схем PlantUML. | `.puml` и их общие фрагменты. |
| `mkdocs.yml` | Тема, расширения, порядок верхних разделов и оформление навигации. | Только при изменении общих правил сайта. |
| `docs/tools/` | Генерация диаграмм, обновление зависимых страниц и проверки. | Когда меняется сам процесс сборки. |
| `.site-docs/` | Собранный сайт. | Ничего: каталог генерируется и не попадает в Git. |

Страницы внутри `docs/` образуют вложенное меню по папкам. Файл `index.md` — обзор раздела, другие `.md` — его подразделы. Верхний порядок закреплён в `mkdocs.yml`, а список страниц внутри разделов определяется существующими файлами. Подробные правила — в [структуре документации](01-structure.md).

## Как изменение попадает на сайт

1. Измените Markdown и, если нужна схема, её текстовый исходник.
2. Для IDEF0 генератор пересоздаст SVG из `.idef0` и JSON перед сборкой сайта. Для PlantUML расширение создаст SVG при обработке страницы с блоком `plantuml`.
3. `make docs` показывает результат в браузере и обновляет страницу при изменениях. `make docs-build` собирает статический сайт; `make docs-test` дополнительно проверяет его.
4. Проверьте, что подписи, ссылки и границы модели соответствуют тексту страницы. Сохраняйте в Git исходники, Markdown и создаваемые IDEF0-SVG.

```sh
make docs          # Сайт с обновлением в браузере
make idef0-render  # Явно обновить все IDEF0-SVG
make docs-build    # Статическая сборка
make docs-test     # Строгая сборка и проверки
```

Для запуска нужен Docker Compose. Команды выполняются из корня репозитория; локальные настройки сайта описаны в [«Начало работы»](../getting-started/index.md).
