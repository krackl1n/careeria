# Команды PlantUML в документации

На [главной странице PlantUML](index.md) показано, где хранить `.puml` и как устроена пересборка. Здесь собран синтаксис, который нужен для подключения схем к Markdown и повторного использования C4-модели.

## Блок `plantuml` в Markdown

Откройте блок тремя обратными кавычками и укажите язык `plantuml`. MkDocs превратит содержимое блока во встроенный SVG. Внешние четыре кавычки ниже служат только для показа примера:

````markdown
```plantuml
@startuml
!include architecture/c4-plant-uml/plantuml/context/system-context.puml
@enduml
```
````

Путь после `!include` во встроенном блоке считается от `docs/`. Для файла `.puml`, который сам подключает другие `.puml`, пути могут быть относительными к этому файлу.

## `@startuml` и `@enduml`

Эти строки открывают и закрывают одну диаграмму. В блоке Markdown размещайте их вокруг `!include` или описания элементов. Незакрытая диаграмма не будет корректно отрисована.

```text
@startuml
Alice -> Bob: Пример сообщения
@enduml
```

## `!include`

Подставляет содержимое другого `.puml` в текущую диаграмму. В Careeria так подключаются общие определения из `model/`, стили из `common/` и готовые виды на Markdown-страницах.

```text
!include architecture/c4-plant-uml/plantuml/context/system-context.puml
```

Используйте существующий файл и проверяйте путь от места запуска рендерера. Для Markdown-блока он считается от `docs/`; рабочий пример есть на [странице системного контекста](../../architecture/c4-plant-uml/plantuml/context/system-context.md).

## `!startsub`, `!endsub` и `!includesub`

Пара `!startsub ID` и `!endsub` помечает именованный фрагмент в `.puml`. Команда `!includesub путь!ID` подключает только этот фрагмент. Это полезно, когда один исходник содержит несколько представлений или общих определений.

```text
!startsub L2
Alice -> Bob: Сценарий L2
!endsub
```

Подключение фрагмента на странице:

````markdown
```plantuml
@startuml
!includesub architecture/c4-plant-uml/plantuml/example.puml!L2
@enduml
```
````

`example.puml` здесь условный путь: сначала создайте исходник с такой секцией. Если исходник содержит один вид, используйте `!include`.

## `$link` в элементах C4

Параметр `$link` задаёт адрес, по которому можно перейти нажатием на элемент диаграммы C4. Его указывают в объявлении элемента, например `System`, `Container` или `Component`. На Markdown-странице рядом со схемой добавьте обычную ссылку на тот же уровень, чтобы переход был виден и без нажатия на SVG.

```text
System(careeria, "Careeria", "Система подбора", $link="/architecture/c4-plant-uml/plantuml/container/full-system/")
```

Ссылка с начальным `/` рассчитана на сайт в корне домена. При публикации в подкаталоге проверьте адреса. Реальный пример есть в [исходнике системного контекста](../../architecture/c4-plant-uml/plantuml/context/system-context.puml).

## Команды проверки

| Команда | Когда запускать |
| --- | --- |
| `make docs` | Открыть сайт и увидеть SVG на странице после сохранения Markdown или `.puml`. |
| `make architecture-validate` | Проверить исходники архитектурных схем PlantUML. |
| `make docs-build` | Собрать статический сайт. |
| `make docs-test` | Дополнительно проверить диаграммы и внутренние ссылки. |

Команды выполняются из корня репозитория. Для локального сайта и сборки нужен Docker Compose.
