# Архитектура C4 — Уровень 4: Детализация кода (L4 Code)

Уровень **C4 Code (L4)** представляет собой наиболее подробный срез архитектурной модели Careeria. Он раскрывает внутреннее устройство **отдельных ключевых компонентов уровня L3** в виде объектно-ориентированных UML-диаграмм классов, интерфейсов и связей.

## Назначение уровня L4

В соответствии с методологией Саймона Брауна (автора C4):
1. **L4 строится точечно (on-demand):**  
   Мы не создаем гигантскую диаграмму классов на все микросервисы сразу. L4 применяется только к тем компонентам, которые содержат нетривиальную доменную логику, конечные автоматы состояний (FSM), межагрегатные правила или сложные паттерны.
2. **Границы диаграммы строго соответствуют L3-компоненту:**  
   Внутрь L4-диаграммы конкретного сервиса **не включаются** соседние компоненты и инфраструктурные адаптеры (БД, сетевые клиенты, gRPC-серверы). Связи с ними показываются исключительно в виде исходящих **интерфейсов-портов (Ports & Repositories)**.
3. **Чистая архитектура и строгая типизация моделей:**  
   В проекте исключено размытое понятие «DTO». Модели данных строго разделены по слоям их назначения:
   * **Транспортный уровень (Transport / Adapters):** `Request` и `Response` (сетевой протокол, сериализация protobuf/JSON).
   * **Прикладной уровень (Application / Use Cases):** типизированные `Input` (входные параметры операции) и `Output` (результат выполнения сценария).
   * **Доменный уровень (Domain Core):** `Aggregate Root`, `Entity`, `Value Object`, `Domain Policy`, `Domain Projection`.
   * **Слой репозиториев (Repository / Storage):** на границе репозиторий принимает и возвращает **доменные сущности**, а внутри себя преобразует их в **`Data (Raw)` модели** (табличные строки базы данных, сгенерированные `sqlc` структуры `*Row`).

## План перехода к автогенерации из Go

В текущей версии спецификации диаграммы классов оформлены декларативно в PlantUML (`.puml`). При реализации backend-кода на языке Go планируется подключение автоматической генерации:

1. **Использование утилиты `goplantuml` / собственного AST-генератора:**  
   Сканирование пакетов `internal/domain` и `internal/app` для извлечения структур, интерфейсов и их взаимосвязей на основе статического анализа кода Go (`go/ast`, `go/types`).
2. **Встраивание в CI / Makefile:**  
   Добавление сборочной цели `make generate-code-architecture` для автоматического обновления L4-диаграмм при изменении сигнатур доменных методов и структур.
