# System Landscape (L0)

Карта систем, участвующих в подборе и последующем кадровом учёте. Область схемы — взаимодействие Careeria с работодателями и внешними поставщиками. Это целевое представление архитектуры: оно не означает, что все интеграции уже реализованы.

## Как читать диаграмму

Диаграмма читается слева направо, как landscape участника Member 2. Отдельно показаны кандидат, рекрутер, нанимающий руководитель и администратор компании. Границы `Enterprise_Boundary` разделяют продуктовую экосистему Careeria и корпоративный ИТ-ландшафт работодателя. Провайдер аутентификации и поставщики уведомлений находятся за пределами этих границ.

`Person` обозначает роль пользователя, `System` — Careeria, `System_Ext` — независимую внешнюю систему. Стрелки подписаны действием и способом обмена; направление соответствует запросу или передаче данных. Цвета и типы элементов объясняет легенда.

| Участник или система | Роль в экосистеме |
|---|---|
| Кандидат | Ищет вакансии, откликается и проходит отбор в Careeria. |
| Рекрутер | Публикует вакансии, ведёт отклики, интервью и офферы; работает с кадровыми заявками в HR-системе работодателя. |
| Нанимающий руководитель | Оценивает кандидатов и согласует решения о найме. |
| Администратор компании | Управляет профилем работодателя, участниками компании и корпоративными ролями. |
| Careeria | Платформа подбора: вакансии, отклики, оценивание, коммуникации и сопровождение процесса найма. |
| Employer HR System | Класс корпоративных кадровых систем работодателей. Принимает результаты найма и передаёт изменения в Careeria; конкретный продукт не зафиксирован. |
| Identity Provider | Внешняя аутентификация и федерация входа. В текущей модели используется OIDC-провайдер на базе Keycloak. Это отдельная зависимость, а внутренний Identity Service остаётся частью Careeria. |
| Notification Providers | Внешние поставщики доставки: SendGrid, Firebase Cloud Messaging и Twilio. На L0 объединены в одну группу систем; внутренний Notification Service остаётся частью Careeria. |

Границы показывают принадлежность систем, а не сетевые подсети или место размещения. Careeria передаёт результаты найма в HR-систему и принимает кадровые изменения через webhooks. Провайдеры уведомлений принимают запросы Careeria и доставляют сообщения кандидатам и рекрутерам. Работа рекрутера с HR-системой показана как бизнес-связь; конкретные права в чужой системе эта модель не задаёт.

## Что раскрывается на следующем уровне

В проекте **L0** — обозначение [System Landscape](https://c4model.com/diagrams/system-landscape), дополнительного представления C4. Здесь рассматривается экосистема из нескольких систем. [Контекст системы (L1)](../system-context%28L1%29/index.md) выбирает Careeria и подробнее показывает её пользователей и непосредственные внешние зависимости.

На L0 не раскрываются внутренние микросервисы, хранилища, брокеры и узлы размещения. Способы межсистемного обмена указаны на связях без детализации внутренних API. Контейнеры описываются в [полной системе (L2)](../system-context%28L1%29/full-system%28L2%29/index.md), размещение — на [диаграммах развёртывания](../deployment/README.md). Порядок обмена с HR-системой раскрывается в [динамическом сценарии](../dynamic/hr-integration.md).

Нажмите на Careeria в диаграмме, чтобы открыть её **L1**. [Исходник PlantUML](system-landscape.puml) можно использовать для изменения схемы.
