# AuthZ Synchronization Service (L3)

<!-- excerpt -->

AuthZ Synchronization Service читает доменные события из Kafka и обновляет отношения доступа в OpenFGA. Например, после публикации вакансии сервис добавляет право на чтение её карточки.

Потребитель декодирует событие с использованием схемы из Registry. Компонент преобразования сопоставляет изменение объекта с отношениями между пользователями, компаниями и ресурсами. Клиент OpenFGA применяет добавление или удаление рассчитанных отношений. Обновление выполняется асинхронно после доменной транзакции, поэтому результат зависит от прохождения события через очередь.

<p align="right">Таблица - Элементы. Компоненты AuthZ Synchronization Service</p>

| Элемент | Тип или технология | Назначение и ответственность |
|---|---|---|
| Потребитель изменений | Go / Kafka | Читает доменные события из Kafka, получает нужную версию Avro-схемы и передаёт декодированное изменение на обработку. |
| Преобразование отношений | Go | Сопоставляет тип и содержание события с моделью доступа. Формирует кортежи для добавления или удаления, указывая субъект, отношение и объект. |
| Клиент записи отношений | Go / OpenFGA API | Записывает рассчитанные изменения и возвращает результат обработки. Повторное получение одного изменения должно приводить к тому же состоянию отношений. |
| Kafka | Apache Kafka, KRaft | Событийная шина платформы. Хранит доменные сообщения в топиках и передаёт их группам потребителей для независимой асинхронной обработки. |
| Schema Registry | Apicurio Registry, Avro | Хранилище версий схем событий Avro на базе Apicurio Registry. Издатели и потребители получают схемы для сериализации и чтения доменных сообщений. |
| OpenFGA | OpenFGA, PostgreSQL | Сервис проверки доступа на основе отношений между субъектом и ресурсом. Доменные сервисы запрашивают решение о доступе, а обработчик синхронизации обновляет отношения по событиям платформы. |

<p align="right">Таблица - Назначение компонентов AuthZ Synchronization Service</p>

| Компонент | Назначение |
|---|---|
| Потребитель изменений | Читает доменные события из Kafka, получает нужную версию Avro-схемы и передаёт декодированное изменение на обработку. |
| Преобразование отношений | Сопоставляет тип и содержание события с моделью доступа. Формирует кортежи для добавления или удаления, указывая субъект, отношение и объект. |
| Клиент записи отношений | Записывает рассчитанные изменения и возвращает результат обработки. Повторное получение одного изменения должно приводить к тому же состоянию отношений. |

Между фиксацией изменения в доменной базе и обновлением отношений проходит время доставки события. При обработке пользовательского запроса доменный сервис обращается к OpenFGA за решением о доступе. Синхронизация отношений выполняется в фоне.
