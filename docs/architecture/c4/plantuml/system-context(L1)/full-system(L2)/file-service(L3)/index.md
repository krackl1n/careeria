# File Service (L3)

<!-- excerpt -->

File Service выдаёт временную ссылку на загрузку в объектное хранилище, проверяет загруженную версию и связывает её с ресурсом платформы. Привязка определяет, какую версию файла можно скачать.

Файловый API принимает команды от шлюза и доменных сервисов с контекстом полномочий. Компонент загрузки ведёт сеанс, компонент проверки анализирует содержимое конкретной версии и запрашивает антивирусное заключение. После успешной проверки файл может быть связан с ресурсом платформы. Репозиторий сохраняет состояние операций, а обработчик очистки удаляет освобождённые объекты с учётом действующих привязок.

<p align="right">Таблица - Элементы. Компоненты File Service</p>

| Элемент | Тип или технология | Назначение и ответственность |
|---|---|---|
| Файловый API | gRPC | Принимает идентификатор операции и контекст вызывающей стороны. Проверяет разрешения на действие с файлом или привязкой с учётом полномочий доменного сервиса. |
| Управление загрузкой | Go | Выдаёт краткоживущее право загрузки, обрабатывает завершение и отмену. После завершения передаёт точную версию объекта на проверку. |
| Проверка файла | Go | Сверяет размер, фактический MIME-тип и контрольную сумму. Запрашивает антивирусное заключение. Версия становится доступной только после успешного завершения всех проверок. |
| Управление привязками | Go | Создаёт и освобождает привязки. Для скачивания проверяет действующую привязку и выдаёт временную ссылку на проверенную версию. |
| Обработчик очистки | Go | Выбирает задачи очистки, проверяет оставшиеся привязки и сроки прав на запись, отменяет незавершённые загрузки и удаляет освобождённые объекты. |
| Репозиторий метаданных | Go / SQL | Сохраняет состояние файла, сеанса загрузки и привязок в File DB. Устойчивые идентификаторы позволяют сопоставить повторную команду с ранее начатой операцией. |
| Клиент хранилища | MinIO Go SDK | Подписывает ограниченные ссылки, управляет составной загрузкой, читает версию для проверки и выполняет физическое удаление. |
| Candidate Service | Go, gRPC, Protobuf, pgx, sqlc | В Candidate Service один компонент ведёт профиль кандидата, другой управляет версиями резюме. Данные профиля и версий хранятся в Candidate DB, а загрузку и скачивание документов обеспечивает File Service. |
| API Gateway | Go, grpc-gateway, grpc-go, OpenTelemetry | API Gateway принимает HTTP-запрос от BFF, проверяет предъявленный токен по открытым ключам Identity и применяет политику доступа к методу. Доменный сервис получает вызов по gRPC. |
| OpenFGA | OpenFGA, PostgreSQL | Сервис проверки доступа на основе отношений между субъектом и ресурсом. Доменные сервисы запрашивают решение о доступе, а обработчик синхронизации обновляет отношения по событиям платформы. |
| Object Storage | MinIO, S3 API | Приватное объектное хранилище файлов на базе MinIO. File Service управляет версиями и ограниченными ссылками, а браузер передаёт содержимое по выданному разрешению. |
| File DB | PostgreSQL | Метаданные файлов, сеансы загрузки, привязки и задачи очистки. |
| Антивирусный сканер | Интерфейс сканирования | Проверяет содержимое переданной версии. |

Клиент передаёт байты непосредственно в Object Storage по временной ссылке. Один файл может удерживаться несколькими ресурсами. Например, удаление версии резюме из профиля освобождает её привязку, а экземпляр, связанный с откликом, остаётся доступным в рамках прав на этот отклик.
