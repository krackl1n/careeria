# 4.3. Хранилища данных и процесс CI/CD

## Хранилища и границы владения данными

Каждый сервис владеет собственной схемой или базой данных **PostgreSQL** (`Candidate DB`, `Company DB`, `Vacancy DB`, `Hiring DB`, `Assessment DB`, `Communication DB`, `Identity DB`, `Integration DB`):

- прямое обращение одного сервиса к таблицам другого запрещено;
- синхронное чтение данных другого домена выполняется через его gRPC API;
- асинхронная синхронизация и построение read-моделей выполняются через события Kafka;
- физические файлы хранятся в **S3 / MinIO**, а в реляционных таблицах сохраняется только `file_id`.

## Сводка границ ответственности

| Домен / Сервис | Зона ответственности |
|---|---|
| **Candidate** | Профиль, резюме и предпочтения кандидата |
| **Company** | Организация-работодатель, участники и корпоративные роли |
| **Vacancy** | Описание, условия и жизненный цикл вакансии |
| **Hiring** | Отклик (`Application`), этапы отбора и state machine найма |
| **Assessment** | Тестирование, практические задания и Live Coding |
| **Communication** | Диалоги, групповые чаты и сообщения |
| **Identity** | Аутентификация, токены и пользовательские сессии |
| **OpenFGA** | Отношения авторизации (ReBAC) |
| **Notification** | Многоканальная доставка уведомлений |
| **File** | Загрузка, проверка и хранение файлов в S3 / MinIO |
| **Integration** | Входящие и исходящие HR-webhooks |

## Конвейер CI/CD

В целевом контуре поставки используются **Git**, **Jenkins**, **Docker**, **Kubernetes** и **Argo CD**:

```text
Git ──▶ Jenkins CI (Build, Unit/Integration Tests, Lint, Proto & Avro Checks)
    ──▶ Docker Image ──▶ Container Registry
    ──▶ GitOps Manifests ──▶ Argo CD ──▶ Kubernetes
```

- **Jenkins** выполняет сборку, модульные и интеграционные тесты, линтинг и проверку совместимости контрактов Protobuf/Avro.
- **Argo CD** обеспечивает декларативную GitOps-доставку в кластер **Kubernetes**.
- Команды локального и серверного запуска Compose-окружений приведены в разделе [Развёртывание](../../deployment/index.md).
