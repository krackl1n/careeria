# 4.2. Информационная структура программного обеспечения

## Модель данных в нотации ER

Физическая модель данных Careeria представлена отдельными схемами сервисов. Каждая схема показывает принадлежащие сервису таблицы, их атрибуты, ключи и связи. Диаграммы используют нотацию «воронья лапка» для обозначения кратности и обязательности связей.

Единая физическая диаграмма всей системы не приводится: каждый сервис владеет собственными данными и логической базой, а общая схема со всеми таблицами и связями была бы трудно читаемой. Логические базы могут размещаться в общем кластере PostgreSQL; такое размещение не объединяет модели данных сервисов.

На диаграммах PK обозначает первичный ключ, FK - внешний ключ, звёздочка - обязательное поле. Круг обозначает необязательную связь, черта - один объект, лапка - множество. Составной внешний ключ показан линией к последнему полю и перечислен в таблице связей. Внешние идентификаторы других сервисов не образуют межбазовых внешних ключей.

В таблице связей приведены два значения: сколько записей дочерней таблицы может ссылаться на одну запись родительской таблицы и сколько родительских записей может относиться к одной дочерней. Например, у одного кандидата может быть несколько резюме, а каждое резюме принадлежит одному кандидату. Минимум дочерних записей равен нулю. Кратность определяется обязательностью и уникальностью ключей; дополнительные ограничения могут её сузить. Для атрибутов указаны тип, обязательность, ключи, значения по умолчанию и смысл.

В приведённых ниже разделах представлены диаграммы, назначение сущностей, связи, атрибуты и ограничения. Модель Identity разделена на несколько диаграмм по предметным областям. Данные принадлежат соответствующим сервисам; ссылки между сервисами передаются по контрактам и не образуют внешних ключей между их схемами.
